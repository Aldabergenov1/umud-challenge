# Просмотрщик разметки

Локальное веб-приложение на Streamlit. Выбираешь тестовый кадр, модели его размечают, и на картинке видно,
что они нашли и откуда взялись числа PA, FL и MT. Можно загрузить и свой кадр.

## Что нужно

1. Окружение из `requirements.txt` в корне репозитория, streamlit там уже есть.
2. Тестовые кадры в `data/raw/test_images_v2/test_set_v2/`. Как скачать, написано в README в корне.
3. Веса моделей в `work/`: `apo_fold0.pt` … `apo_fold4.pt` и `fasc_fold0.pt` … `fasc_fold4.pt`, по 122 МБ.
   В git их нет. Их можно обучить ноутбуком (от 2.5 до 3 часов на GPU) или взять готовые у владельца репозитория.
   Хватит и одной пары, `apo_fold0.pt` + `fasc_fold0.pt`: приложение само увидит, какие фолды есть.

Не обязательно, но полезно: `work/test_probs.pkl` с масками последнего полного прогона ноутбука. Если он
лежит в `work/` и выбраны все фолды, кадры открываются мгновенно, без инференса.

## Запуск

Из корня репозитория:

```bash
streamlit run app/app.py
```

Откроется http://localhost:8501. Первый запуск около минуты читает шкалы всех 309 тестовых кадров, потом это
берётся из кеша. Видеокарта не нужна: на CPU один фолд размечает кадр примерно за 2 секунды, пять фолдов
примерно за 8.

## Что на экране

Большая картинка показывает УЗ-область в масштабе 1 мм = 16 пикселей, внизу полоска длиной 10 мм.

| Цвет | Что это |
|---|---|
| красный | поверхностный апоневроз, маска и прямая по её нижнему краю |
| синий | глубокий апоневроз, маска и прямая по верхнему краю |
| зелёный | карта фасцикул |
| жёлтый | фрагменты фасцикул, по которым считается PA |
| розовый | три замера MT |
| бирюзовый | фасцикула под итоговым углом PA между апоневрозами |

Справа исходный кадр с найденной УЗ-областью и все промежуточные числа. Там же можно сравнить кадр с любым
сабмитом из `work/*.csv`.

Слева настройки, они меняют результат сразу:
- какие фолды брать в ансамбль;
- способ расчёта PA;
- сдвиг PA и множитель FL;
- поправка неквадратных пикселей для кадров Telemed со шкалой слева;
- какие слои показывать.

«Итог» в метриках складывается из сырого замера, калибровки (`work/calibration.json`, если его нет, то
`app/calibration.json`) и сдвигов из боковой панели. В сабмите поверх этого ещё берётся медиана по
5-кадровой серии, поэтому числа там могут слегка отличаться.

## Ручная разметка

Вторая страница в боковом меню (annotate) нужна, чтобы вручную мерить тестовые кадры. Веса моделей для неё не нужны.

1. Слева впиши имя латиницей, метки сохранятся в `labels/<имя>.json`.
2. Клавиша `1`: 2–4 точки по нижнему краю поверхностного апоневроза. Клавиша `2`: так же по верхнему краю
   глубокого. Клавиша `3`: каждая фасцикула двумя кликами вдоль хорошо видного волокна, хотя бы три ближе к центру.
   Пунктир показывает, насколько фасцикулу пришлось продлить.
3. `Z` отменяет последний клик, `S` сохраняет и открывает следующий неразмеченный кадр.

Над картинкой сразу видны PA, FL и MT по твоим кликам. По умолчанию показывается один кадр из каждой серии
(197 вместо 309), его метка расходится на всю серию. Кадры поделены по имени: `makhambet` видит половину A, `arman` половину B. Шесть серий Telemed есть у обоих, по ним видно, насколько разметчики расходятся. Любое другое имя видит все кадры. Раскладки внутри половины идут вперемешку, поэтому даже частично сделанная половина покрывает все аппараты. Пошаговая инструкция для второго разметчика есть в README в корне. Прогноз модели скрыт, чтобы не подстраиваться под него.

`python scripts/manual_labels.py` собирает метки всех разметчиков в `labels/manual_mean.csv` и считает метрику
соревнования для каждого сабмита из `work/`.

## Как устроено

`app/core.py` не копирует код конвейера, а берёт функции прямо из `notebooks/umud_pipeline.ipynb`. Из ячеек
выполняются только импорты, определения функций и константы, а обучение и прогон бенчмарка пропускаются.
Если поменять геометрию в ноутбуке, приложение подхватит изменения после перезапуска.
